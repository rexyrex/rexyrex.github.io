슬쩍 — accessibility disclosure demonstration

Release 1.1.1 (4), com.rexyrex.katalk_keeper. Fresh install on an Android 15 device. English captions under the screen describe each step.

  1. 0:00 The app is opened from the device home screen.
  2. 0:04 First-run onboarding — the normal app flow, no menu or settings navigation.
  3. 0:30 The prominent disclosure for the AccessibilityService API appears on its own screen (“접근성 서비스 사용 안내”): what is read, why, stored on this device only, never shared, no automated actions, and how to opt out.
  4. 0:48 The user taps “동의 안 함” (Do not agree). No consent is recorded; the service stays off and reads nothing.
  5. 0:57 The disclosure is shown again from Settings → “접근성 서비스 (선택)”.
  6. 1:06 The user taps “동의하고 화면 수집 켜기” (Agree and turn on). Consent is recorded in the app before Android’s Accessibility settings open.
  7. 1:14 The user enables “슬쩍 화면 수집 (선택)” and allows it in Android’s system dialog.
  8. 2:08 Back in the app, the accessibility service shows 켜짐 (On).

The service reads only KakaoTalk chat screens (packageNames="com.kakao.talk") to archive messages shown while a chat is open and to detect KakaoTalk’s “deleted message” placeholder. It does not click, type, send messages, or read other apps. Everything stays on the device; nothing is transmitted or shared. The service reads nothing until the user has agreed to the in-app disclosure — even if it is switched on directly from Android settings — and declining withdraws consent. The same disclosure is also presented automatically when the service is on without consent, and from a suggestion on the home screen.

Live KakaoTalk capture is not shown: it needs a signed-in KakaoTalk account, which this test device does not have.
